At 2026-10-08T19:16:25Z the orders API returned a 5xx error for a GET /orders/999999 request. The service threw a TypeError: 'NoneType' object is not subscriptable when trying to build the response from an order object that was None. ## 5. Root Cause
The root cause is application logic that assumes an order lookup always returns a dict (order) and does not check for a missing result (None) before subscripting its keys. When a request for a non-existent order id (999999) is processed, order is None and subscripting order["id"] triggers the TypeError, leading to a 5xx error.

Evidence supporting this:
- The stack trace points directly to the line that subscripts order.
- The TypeError specifically indicates subscripting on None.

This is a code bug (application logic) — not an infrastructure, network, or external dependency outage.
